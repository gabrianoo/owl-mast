# automation

Engineering automation for Owl Mast, separate from the product backend.

- `unattended/` — the unattended execution foundation (ENG-01): GitHub-authoritative dispatch, synchronization and T3 coordination policy. On the real GitHub transport every state command is opt-in only: it needs a current, run-bound activation authorization (`--activation`); the shipped policy and the committed candidate activation are unapproved and refuse. Guide: [docs/unattended-execution.md](../docs/unattended-execution.md).
- `policy.toml` — default policy (empty allowlist: nothing dispatchable). `examples/first-run-om-01-02.toml` is the candidate first-run policy and `examples/activation-om-01-02.candidate.toml` the unapproved candidate activation (never commit an approved one).
- `tests/` — stdlib `unittest` qualification suite with an in-memory GitHub transport and the real backlog snapshot fixture. Run `python3 -m unittest discover -s automation/tests -t .` from the repository root (Python 3.12, no dependencies). `tests/test_final_findings.py` covers the six defects of the final PR #107 disposition, `tests/test_fresh_review_findings.py` the four code findings of the fresh review of remediation pass 1 `tests/test_activation.py` the explicit opt-in (admission, drift, expiry, cleanup, restart, CLI default refusal), `tests/test_enabling_repair_1.py` the six findings of the independent review of the enabling change (missing run metadata, binding provenance, source re-read, strict timestamps, nested target keys, durable expiry stop), `tests/test_enabling_repair_2.py` and `tests/test_enabling_repair_3.py` the later rounds (foreign run record, persisted temporal facts, status under the gate; source re-read at creation, one clock observation per operation), `tests/test_repair_pass_2_findings.py` the two findings of the fresh review of repair pass 1 (unresolved task authorizations as ownership obligations; done-intent reconciliation behind every fresh-attempt gate), and `tests/test_pr114_round7_findings.py` the 17 findings of the round-7 review of PR #114 (issue #118), one class per finding: the use ledger's damaged and moved records (`field`, `consequence`), the recovered `run-started` line, the clock-stop report (`presented_current`, `clear_requires`), state stamps under a clock stop and the bounded git timeout, followed by round 1 of PR #185, six classes for the walkthrough risks R1-1 to R1-5 (R1-5 has two): no clock stop from `_authorize` and nothing issued while the clock reads before the mark (`clock-behind-mark`), the run-order check against an `issued_at` that is never before the mark, a stamp that is the clock except under a recorded `clock-regression` stop, the damaged-record rule on records the tool wrote and on restored ones, journal lines written before `field` existed that still dedupe, and the reaped git child; `PYTHONPATH=. python3 automation/tests/probe_final_findings.py`, `… probe_fresh_review_findings.py` and `… probe_repair_pass_2_findings.py` re-run those scenarios as readable transcripts.
