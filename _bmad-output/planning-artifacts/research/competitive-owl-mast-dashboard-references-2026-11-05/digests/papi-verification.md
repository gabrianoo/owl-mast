# PAPI verification — 2026-11-05

Focused public-source check; no account, installation, credentials, or product execution. Confidence is in what the vendor documents, not independent validation of delivered functionality.

- **Core description supported.** Vendor documents describe shared planning, decisions, handoffs, build reports, human review and release through hosted MCP and a dashboard. The features page illustrates cycle workflow, decision records and a live hub. The vendor repository explicitly describes its own task board. [Features](https://getpapi.ai/features), [runbook](https://getpapi.ai/llms.txt), [vendor README](https://github.com/getpapi/papi)
- **Pricing supported, with a narrower phrasing.** Free is €0 with three projects and unlimited cycles; Pro lists cross-project lessons and one collaborator; Team lists shared projects/roles, shared task pool and API/BI export. Say “the reviewed public pricing page does not display a numeric paid-plan price”: Pro says checkout; Team says custom. Do not generalize that no public numerical price exists anywhere. [Pricing](https://getpapi.ai/pricing)
- **Licensing/export description supported.** Trust describes closed-source hosted engine/dashboard, an Elastic License 2.0 local server package, an MIT guides/config repository, and project exports in Markdown, JSON or CSV on every tier. Team API/BI export should not be conflated with these basic exports. [Trust](https://getpapi.ai/trust)
- **AI exception matters.** Pricing broadly says PAPI runs no AI; Trust narrows this to the normal loop and discloses backend Anthropic extraction when a user uploads a brief during onboarding, plus optional locally configured Anthropic commands. Describe a marketing simplification with a disclosed exception, rather than claiming the ordinary workflow secretly uses hosted AI. [Pricing](https://getpapi.ai/pricing), [Trust](https://getpapi.ai/trust)
- **Local-install inconsistency is stronger and more specific than proposed.** The runbook says no package/local process, yet its own footer links an advanced local server package. Vendor installation docs expressly describe remote recommended and local advanced transports. This appears to conflate default setup with all supported deployment paths; local runtime does not establish a fully self-hostable product. [Runbook](https://getpapi.ai/llms.txt), [install guide](https://github.com/getpapi/papi/blob/main/docs/install.md)
- **Additional documentation-quality issue:** the fetched production-domain runbook embeds `dev.getpapi.ai` and `mcp.dev.getpapi.ai`, while Trust and install docs use production hosts. Flag this as environment ambiguity; do not recommend those development endpoints without clarification. [Runbook](https://getpapi.ai/llms.txt), [Trust](https://getpapi.ai/trust), [install guide](https://github.com/getpapi/papi/blob/main/docs/install.md)
- **Unestablished capabilities remain correctly scoped.** OpenTelemetry, model-spend tracking, an ML budget optimizer and bidirectional Jira sync were not established by the reviewed evidence. This is not proof those features are absent.
- **Independent-source check adds little feature confidence.** Odel reports an endpoint/namespace check but reproduces vendor README content and could not list authenticated tools. Agentery displays an older numerical price observation, which reinforces narrowing the pricing statement, but is not authoritative for current pricing or functionality. Neither is an independent hands-on product review. [Odel](https://odel.app/modules/getpapi/papi), [Agentery](https://www.agentery.com/agents/getpapi)
