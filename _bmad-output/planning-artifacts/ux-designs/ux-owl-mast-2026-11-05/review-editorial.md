# Editorial review — Owl Mast UX spines

**Targets:** `DESIGN.md` (2,305 words) and `EXPERIENCE.md` (5,253 words). Counts come from `word_metrics.py` and include frontmatter. Mockups, the memlog, and source extracts were read for context only.

**Purpose read:** these documents exist to help downstream UX, architecture, and build readers look up how Owl Mast looks and behaves, and to see which statements are confirmed, inherited, proposed, or still open.

**Structure model:** Reference/Database, the closest fit for paired contract spines that readers enter at random. Key Flows follows the bmad-ux named-journey shape inside that model. The DESIGN.md section order is canonical and correct. All required EXPERIENCE.md sections are present in template order. No row asks to reorder canonical sections.

**Standards:** Microsoft Writing Style Guide (configured baseline), reader type `humans`, no length target. Editorial rows carry no severity or rank, and the rows are ordered by comprehension impact.

**Scope of findings:** every row is a document edit. None is a downstream implementation test or an architecture dependency. Rows tagged QUESTION or phrased "Consider" need the author's confirmation. A-1–A-6 stay provisional and unchanged, along with their pointers.

**Style noted and preserved:** telegraphic table fragments, slash shorthand inside tables, arrows for sequence, absolute rules ("never"), canonical title-case headings, DESIGN.md's spelled-out labels ("Designer proposal"), EXPERIENCE.md's bracket tags, and the `DESIGN.md.Components` reference form, which the bmad-ux template also uses. Prose rows flag only places where these habits stop a reader from parsing the meaning.
