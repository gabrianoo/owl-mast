What counts as a work update

Illustrative event contract: every permitted distinct event below triggers push and stays in the feed.

  • Tracker changes: new work, assignment, status, epic membership, and acceptance-criteria or checklist changes.
  • Attention: observed blockers and requests for input.
  • Agent observation: observed agent-state changes.
  • Contribution and evidence: pull-request, check-result, and merge events.

Separate proposed default-on notices: knowledge lifecycle and delivery events, and connection failure or recovery. These are additional notice classes; they do not narrow the every-work-update default. Any category preference must leave the default work-event set intact unless the user explicitly changes that policy.

Before sending anything, verify this recipient’s access to the source record. An unauthorized or unverifiable event produces no push, including no generic push, and no feed entry. This is permission enforcement, not throttling.

Distinct events retain distinct notification identities; only replayed copies deduplicate. Platform stacking must not discard updates. Denied or unsupported push leaves authorized in-app updates usable.
