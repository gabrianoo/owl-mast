Counting rules, coverage and unavailable states

One load: a successful, uniquely identified agent read/load of an exact skill or memory version. Search results, human catalog views, attempted reads and source-page creation are not loads. Delivery and load evidence remain separate when the collector distinguishes them.

Different counters: observed skill invocation or memory application needs a task event. Verified useful reuse also needs permitted task evidence and human verification. These are not inferred by subtracting or multiplying load counts.

Incomplete and unsupported: partial sources show observed subtotals; unsupported counters show Unavailable. Zero is used only when a supported, fully observed selected window contains no matching events.

Permissions: counts, agents, session IDs, machines and drill-down evidence use current source authorization. No hidden-recipient count or inaccessible residual is disclosed. Memory here means authorized project knowledge, not imported personal memories.

Retention: query text, prompts and underlying protected content are not required by these counters; A-3 remains open. This mock does not establish client telemetry capability.
